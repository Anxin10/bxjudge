# BXJUDGE 原始資料優化狀態 — 2026-10-26

目前沿用 `feat/local-judge`，採用可取消的有界預取與明確OpenCV執行緒預算，並將既有原始晃動與動態對位分成兩個CPU階段。最新兩支開發原片的**核心速度PASS（關閉VLM），3/3回合仍需覆核，準確率未驗證**。沒有新增分支、模型訓練或3D合成訓練；原片、原判決與人工覆核不覆寫。

## 已採用的實作

CPU解碼、原始盤面晃動與動態幾何，和主執行緒的單一偵測器重疊執行。最多兩格排隊，不改來源影格順序、像素或判斷門檻；輸出前join。取消會終止並回收該次ffmpeg、解除阻塞讀取，來源及關閉錯誤仍回報；外部取消拋CancelledError，不能算成少格成功。

`config/detection.yaml` 設定 `opencv_threads: 4`，嚴格要求正整數。模型框架匯入可能重設OpenCV，所以在run_batch模型載入後、任何scan／decode／prefetch前才套用。正式判決provenance分別記requested與actual，worker中不變更全域設定；自訂YAML可調整預算，其他硬體不保證同樣加速。

已有out要用 `bxjudge run ... --rejudge` 真正重算才有新計時；單純rerun不會刷新未變影片的耗時。規則、3秒期限、模型與幾何門檻均未改。原始晃動仍相對本影片first-second原圖，沒有先穩定畫面；失敗幾何不沿用、不回填。

## 本輪採用：原始晃動與動態對位重疊

完整原片4619格的診斷量測顯示：原始晃動含解碼占用77.650秒（其中decoder next18.109秒）、anchor對位122.113秒、重新定位3.696秒、偵測100.953秒、native追蹤更新1.434秒。量測有診斷開銷，而且這些區間互相重疊／包含，**不得相加當總延遲**；它證明主要CPU成本不是重新定位重試或追蹤更新。

動態模式現在依次串接三個有界階段：原始解碼／晃動producer → 動態對位producer → 主執行緒單一GPU偵測／追蹤。每個queue最多兩格，各階段只有單一writer；分析前全部join。原始晃動和對位仍讀同一未變動的原圖，沒有省略影格、改演算法、降低迭代或放寬門檻。靜態模式維持單producer。

正常來源耗盡不設定共享取消，讓下游排空影格；提前退出／出錯則取消整條串流、終止並回收該次解碼程序。真正來源／關閉錯誤及外部取消保留；正常提前停止不重拋自己清理造成的取消。這個清理問題已經RED重現、修正並經唯讀複審。

乾淨短片ABBA比較（完整暖機後、同兩段各8秒CRF18衍生片、正式模型、CV4、各模式兩次）：上版21.947／20.769秒，重疊版19.806／20.014秒，平均21.358→19.910秒，減少6.8%，仍超過16秒。判決、軌跡、raw motion與480格幾何狀態一致，最大探測點差0.000173px；不同片段的收益不等於整場收益。模型初始化5.317秒、2格detector暖機0.276秒與完整pipeline暖機21.663秒分開記錄。第一輪曾與focused測試重疊，明確排除作最終速度證據；此組修正版獨立重跑。

## 執行緒預算的成對驗證

使用既有兩段各8秒CRF18原片衍生片、同一正式RF-DETR TensorRT FP16。完整核心流程先暖機一次，再按正反序：`sequential1 → prefetched1 → prefetched4 → prefetched4 → prefetched1 → sequential1`，每模式2次。

| 模式 | 完整batch wall兩次（秒） | 平均（秒） |
| --- | --- | ---: |
| 依序／1執行緒 | 43.723、43.178 | 43.451 |
| 預取／1執行緒 | 32.676、33.437 | 33.057 |
| 預取／4執行緒 | 26.606、26.436 | 26.521 |

此組：預取比依序減少23.9%，4執行緒比預取1執行緒再減少19.8%，合計減少39.0%。不是可普遍套用的固定加速比例。六輪判決欄位、原座標軌跡、480格幾何接受／狀態／段落及phase診斷相同；四角與中心探測點最大差0.0000013px。另3支原片96格快取中，raw motion值、有限值mask、碰盤門檻比較與幾何狀態一致，不能推成全片raw motion逐位元相同。

系統背景與溫度未完全控制，正反序降低順序偏差，不給一般化信賴區間。模型載入10.959秒、完整warmup33.794秒另列；最初2格detector priming未單獨計時，不能說所有cold-start成本都已記錄。occupied stage時間互相重疊，不能相加當總延遲。已保留實際執行harness及雜湊；後續harness補priming計時及每模式YAML，但未改寫舊量測。

先前單次短片33.37→25.94秒是另一時段的開發量測；不是這組正反序數據，不能混算平均。更早一組曾與背景pytest重疊，已排除作為速度證據。
