# 遮擋與部分碰撞後重新辨識規格

日期：2026-10-26。狀態：局部人工核對與離線多格外觀診斷已實作；完整重新辨識／聯合指派尚未實作或通過真實驗收。
依據：[軌跡與身分通用規則](2026-10-26-tracking-general-rules.md) G01–G12。
目前核心版本 `6e68fcc`；本次不改短接續、執行 YAML、人工標記、原始判決或既有評估。

## 1. 目標與第一版範圍

在遮擋、重疊或部分碰撞後，評估前後是否為同一顆陀螺，並維持可靠的 X／B 身分。
同時檢查「native track ID 沒變，但物件已認成另一顆」的交換情況。
不以消失、後來落地、出界或勝負倒推身分、發射與缺口內事件；證據不足就保留未知。

第一版採 **候選紀錄模式（shadow）**：輸出候選、拒絕理由與原畫面索引，
不更動既有軌跡成員、X／B、比分、已覆核結果或官方評估人口。
第一版僅在獨立證據中列 `proposed_review_reasons`，不寫回既有 `needs_review`。
日後整合到新的裁判試跑時最多增加必要覆核，不解除舊覆核、不增加自動勝方；
舊結果仍保持原樣。

第一個開發範圍是同一影片、同一已界定回合，超出現有短接續上限而不超過 1.0 秒的
觀測缺口，以及仍有框但經過交疊／疑似交換的局部區間。
1.0 秒是初始實驗範圍，不是已驗證的通用上限；須在新 YAML 顯式記錄，不能把舊
`link_gap_s` 直接改大。更長缺口仍未知。這次不建立可執行設定或假測試結果。

## 2. 四層證據必須分開

| 層次 | 能支持的判斷 | 不能直接推論 |
| --- | --- | --- |
| 原始觀測 | 來源格、框、分數與 native ID | 同 ID 不保證始終同物件 |
| 同物件關係 | 前後片段是否可接續 | 不一定知道是 X 或 B |
| X／B 身分 | 該場身分來源與繼承 | 不決定機械接合、分離、落地或勝負 |
| 裁判事件 | 實際可見事件與正式規則 | 找回身分不能補出缺口內未觀測事件 |

沒有偵測只記 `missing_observation`；框重疊或突然變向只記 `overlap_candidate`／
`impact_candidate`，不得直接當成真正遮擋或碰撞的 GT。
手、發射器、盤緣與高速模糊可能使裁切不可用；`bey_part` 不可當完整陀螺候選。

## 3. 回合範圍與凍結參考庫

### 3.1 範圍先於匹配

提案須帶來源 SHA、`scope_id`、起訖來源格、時間軸／FPS、座標大小。
第一版的可靠 scope 來自人工確認或已獨立驗證的回合邊界。現有自動分段若未驗證於
此用途，只是候選邊界；scope 不明時可列疑點，不得給可採用綁定。

新回合、換手、重新發射或新比賽時重建範圍與參考，不跨場套色或模板。
盤面重定位、幾何失效與來源時間軸限制都要記錄；FPS 或可變影格率時間對應未驗證時，
不能用不可靠時間差取得綁定。不得直接假設已完成跨回合重置能力。

### 3.2 參考必須可靠，不能自我污染

參考限於：該場可靠發射前錨點所支持的清楚觀測，或明確人工確認的該場 X／B 觀測。
人工初始化另行標示，不當全自動成功；用來初始化或調參的片段不能再冒充獨立盲測。
「深色 X／淺色 B」只屬於已確認的那個範圍，不是全專案色彩規則。

每方至少需要三個不同來源格，另須通過最短觀測時間與品質條件；三格只是結構下限，
不是可靠性保證。參考記錄原框、影格、影像雜湊、可見性、身分來源與版本。
掛載時混入手或發射器的框不能直接當清楚陀螺外觀；每張參考的身分與主體範圍都須
有依據，不能只因 native ID 相同就把後來所有畫面都當可靠參考。

參考庫在本次疑點分析前凍結。新找回的候選不能自動加入模板、回頭支持自己，也不能
沿未確認接續累積模板。更新需人工新證據或另經驗收的更新機制，修訂另存；本版沒有
自動更新機制。任一方缺少可區分參考時，可列同物件候選，但不能只比現有一方就替
未知物件定 X／B，也不以排除法補另一方。這類部分證據仍記入 `pair_evidence`，
提案狀態為 `abstained(reference_missing)`，不稱為完整可採用方案。

第一版自動候選的參考影格不得晚於這次疑點開始，避免拿重新出現後甚至未來人工標記
倒過來證明先前身分。日後若允許回溯人工輔助，須另列為離線人工模式與新參考版本，
不能混入第一版自動候選或盲測。

## 4. 片段、品質與外觀證據

### 4.1 分析片段不改原始 track

在疑似遮擋／碰撞區間前後建立衍生片段；即使 native ID 沒變也檢查前後是否一致。
片段以來源 SHA、scope、native ID、原始格區間識別，不切斷或改寫原始觀測。
身分錨點約束已驗證的物件與觀測區間，不把 native ID 當成永久身分。碰撞後的衍生
片段在重新確認前不因沿用 native ID 就自動繼承先前側別；可以提出「同ID已換物件」
的邏輯對應，但不改掉碰撞前錨點或原始 track。只有該碰撞後片段本身也有獨立可靠的
相反身分證據時，才構成不得推翻的錨點矛盾；原生編號相同本身不算這種證據。
一個合併大框不能複製成兩顆；無法分開的重疊框不替雙方取得身分。
旁觀物件、誤偵、零件與賽後拾取仍可未指派，不把所有片段強制分成 X、B 兩條。
新發射、確認結束與另一 scope 都是邊界，重新辨識不能悄悄推翻既有人工事件。

### 4.2 先檢查品質，再比較外觀

只從未畫線、未標字的原始 BGR 影像裁切真實框，保留原座標；描述子縮放不改裁判
或顯示座標。拒絕空框、非有限座標、過小或嚴重截斷裁切；模糊、主體不清、混入其他
陀螺／發射器等情況記品質或可見性不確定，不能硬產生匹配分數。

清晰度、框重疊與信心分數只是品質線索，不是「確定可見」的證明；品質檢查也要用
真實標註驗證，不能把新 heuristic 當可見性 GT。

第一個影子基線使用現有 OpenCV／NumPy 的色彩直方圖與灰階梯度／紋理統計，
多格比較且各項證據須過關。不先裝新 ReID 模型或訓練 3D 模型。
旋轉、反光與角度可能改變描述子，本規格不宣稱旋轉不變或已足夠辨識；相似陀螺
無法分開時維持未知，不靠放寬分數過關。換描述子須重新驗收。

### 4.3 外觀與時空同時成立

不能只取最像的一格。保存每項距離、門檻、參考格、有效樣本數與時間跨度；距離不是
機率，不能顯示成「身分正確率95%」。加權總分不能抵銷幾何或身分硬性矛盾。

時空採原始時間軸與有效盤面參考尺度正規化的距離／速度；外觀取原始裁切。
原始影像與盤面座標分開。缺口內幾何未知時不補舊矩陣；若不能排除盤面移動造成的
歧義，最多保留提案，不能取得可採用綁定。

一般遮擋檢查時間與可達範圍；碰撞後可能變向，不能要求沿同一直線，也不能因「可能
碰撞」就豁免運動限制。碰撞可達範圍須另行校準與驗證，同時過外觀、唯一性及身分
錨點檢查；事件類別不明不能自行選最寬鬆模式。

## 5. 聯合指派與狀態

以下全部成立才產生 `eligible_proposal`：

1. 來源、scope、時間與類別有效，沒有跨新發射、確認結束或新比賽。
2. 凍結參考版本有效，前後有足夠可用實際觀測，必要的 X／B 參考都存在。
3. 多格外觀與時空可達範圍通過，缺失、品質不確定與相反錨點未被忽略。
4. 同時比較 X、B 與未指派選項，兩方對候選及候選對兩方都唯一；同一候選不能給
   雙方，一方不能同時占有兩個不同物件，重複框不當額外獨立證據。
5. 最佳／次佳候選差距與整體配對方案差距都過已凍結門檻；平手或差距不足保持
   未指派，不按位置、native ID、候選順序或分數微差決勝。
6. 在確認窗內至少三個不同來源格及設定的最短時間持續支持同一方案；中間未觀測
   不補值，不把不連續樣本稱為連續可見。
7. 衍生成員沒有循環、重複擁有觀測或相反身分；已可靠觀測到兩個同時存在的物件
   時，不能把它們併成一顆。

狀態流程為 `observed → missing/overlap_candidate → reacquiring → eligible_proposal`。
證據不足進 `abstained`，跨邊界或過期進 `closed`。新證據可建立提案新版本，不抹掉
舊拒絕及當時不確定狀態。這是提案狀態，不是人工「同一顆／不同顆／看不清」GT。

須記錄最晚用到的來源格與 `decision_available_frame`。等待確認窗才取得的身分，不能
假稱從第一個重現影格就已知道；缺口內仍無觀測。另報來源影片時間上的找回／確認
延遲，與電腦實際 wall-clock 分開，不以離線讀取未來影格冒充即時辨識。

第一版所有提案 `applied=false`。必要原因碼：`scope_unverified`、`reference_missing`、
`appearance_unusable`、`appearance_ambiguous`、`geometry_unknown`、
`time_or_reach_conflict`、`anchor_conflict`、`assignment_ambiguous`、
`insufficient_observations`、`new_launch_boundary`、`closed_scope`。

## 6. 證據格式與核心分界

每筆提案必需欄位如下，這次文件工作不建立假結果檔：

| 欄位 | 要求 |
| --- | --- |
| `source_sha256`、`scope_id` | 影片及回合，另存 scope 的人工／驗證來源 |
| `proposal_id`、`supersedes` | 內容／來源與版本識別，修訂另存 |
| `segments` | 原 native ID、起訖來源格與各實際觀測索引 |
| `reference_version`、`reference_sources` | 凍結的每方參考與人工初始化標記 |
| `geometry_reference` | 判定時的快照、逐格變換／未知區間，不讀後來的目前校準冒充 |
| `observations` | 取樣格、原框、裁切／描述子雜湊、品質／可見性狀態 |
| `pair_evidence` | 各項距離、時間、可達範圍、所有候選及最佳／次佳差距 |
| `decision`、`reason_codes` | 提案狀態、拒絕／未知原因與人工可讀解釋 |
| `side_assignment` | X／B／未知，與同物件提案分開；相反錨點不得自動改寫 |
| `applied` | 第一版固定 false，不寫回裁判結果 |
| `decision_available_frame`、`proposed_review_reasons` | 證據何時齊全、待覆核原因；不回寫舊flag |
| `policy_version`、`runtime_provenance` | 描述子／模型／設定與程式版本、FPS／座標語意 |
| `human_review` | 初始未審，後續三態、X／B／未知與修訂來源 |

接線順序：原始偵測／native tracks → 現有短接續及來源成員 → 新提案模組 → 新證據檔
與局部核對頁。新模組只讀輸入，不混入現有 `prepare_launch_tracks` 短接續規則。既有短接續的
成員關係仍只是有來源的演算法結果，不能當人工同物件GT，也不自動擴大可靠參考庫。
在同一次解碼提取小型描述子及必要證據索引，採有界緩衝；不逐格無限保留大圖，不另
做第二次模型推論。參考建立、特徵、提案與證據輸出都計入完整牆鐘。

第一版不解除原有覆核、不增加自動勝方。尚未落地的整合不可聲稱已可自動使用。
任何日後正式成員綁定須另列驗收及變更決策，仍保留原預測與接續來源，不提供相容
fallback，也不把影子模組失敗改成舊半邊猜測。

## 7. 設定及閾值

未來新增獨立 `config/reidentification.yaml`，嚴格驗證必需／未知欄位。缺參數或必要
參數未校準就不能啟用執行中的提案判斷；本次不建立執行設定。校準階段可另用離線
工具計算描述子與距離分布，但不能輸出 `eligible_proposal` 或改寫側別，也不能把
未校準數字填成已驗證設定。最小群組如下：

- 模式：第一版固定 shadow；短接續界線讀既有版本化 policy，初始開發候選上限
  1.0 秒顯式配置，不按影片／顏色／ID 設例外。
- 品質與取樣：最小裁切、清晰度／截斷限制、取樣間隔、參考最低觀測數／跨度、
  找回確認窗、最少觀測格數（不得低於3）、最短時間及記憶體／候選緩衝上限。
- 匹配：色彩及紋理距離上限、兩方與整體配對最小差距、盤面尺度正規化可達範圍；
  遮擋與碰撞條件分開校準，未知事件類別不自行選最寬鬆模式。

用開發用同物件／不同物件／不可辨識片段決定數值，驗收集凍結前固定挑選參考的方法
與全部閾值。正負距離重疊到不能可靠區分時保持未知，不挑一個看似會成功的數字。
這些外觀距離尚未校準，不能把現有0.6 IoU當外觀正確率或直接挪用。

## 8. 人工資料與驗收

### 8.1 少量疑點加上隨機對照

保留的五組拒絕案例只作開發起點，不能標成不同顆真值。取必要前後短片與原尺寸
裁切，只補新疑點，不重做已有三回合覆核。欄位分開記同一顆／不同顆／看不清、
X／B／未知、可見／部分遮擋／不可用、是否確有碰撞；允許不知道。

另抽沒有斷軌但經過交疊的區間及沒有疑點的隨機區間，檢查 ID 持續卻交換身分、
手或發射器混入、相似陀螺與品質誤判。不能只挑低信心案例估全部準確率。
標註、初始化與調參用途留在清單，同片開發資料不能再冒充獨立盲測。

### 8.2 分母與指標

凍結事件／區間人口，不把相鄰影格當成獨立成功樣本。必報總區間、可裁定 GT、人工
看不清／未審、提案、模型未知及真值覆蓋率。所有未知保留在總人口，分開說明：

| 指標 | 計算與限制 |
| --- | --- |
| 錯接比例 | 可裁定且產生同物件可採用提案的案例中，GT為不同顆的比例 |
| 錯側比例 | 可裁定X／B的提案中，side與人工不符的比例；同物件正確仍可能錯側 |
| 找回率 | 可裁定同物件案例中，正確找回的比例；模型未知是未找回 |
| 身分交換 | 可觀測雙方區間的交換次數及區間比例，包含native ID未變的情況 |
| 覆核與覆蓋率 | 對全人口報告；人工未知／未審及模型未知不能從總人口消失 |
| 裁判與完整時間 | 沿用正式評估，時間包含完整新步驟，不只算匹配函式 |

零分母或無真值為未驗證。人工未知不擅自算對或錯；保留人口並報真值覆蓋，模型未知
在可裁定同物件GT上不能算成功。錯接少但全部拒絕也不能通過。

### 8.3 正式自動綁定前的閘門

第一版完成是可重播、可列候選／拒絕及追溯證據，不是已能自動裁判。正式綁定另需：

1. 依影片／回合分開開發與獨立驗收，處理同片事件相關性，不用連續影格灌獨立樣本。
2. 查看驗收結果前凍結錯接／錯側上限、最低找回／覆蓋要求、最少可裁定事件數與
   信賴區間方法。這些數字尚無實測依據，缺決策或樣本不足即未驗證，不能啟用。
3. 相反身分綁定、同觀測給雙方、循環成員、跨scope綁定、修改原始資料是硬性失敗；
   新模組不得產生。觀察到零次錯接不等於證明沒有風險。
4. 保存原回合與原短接續，未解釋的退步不能用合併數或速度抵銷；覆核及未知原因可見。
5. 新完整wall-clock重測。`config/evaluation.yaml`的既有裁判／召回／覆核／速度目標
   不在本規格變更；舊0.897核心速度不能當作新模組已過，VLM是否包含須明寫。

## 9. 實作順序與必要測例

1. 先做只讀scope、凍結參考及局部三態人工資料流程，確認不能偷偷改舊標記／判決。
2. 用保存的偵測與原片建立品質／外觀影子基線及版本化證據。手部、盤緣或模糊裁切
   不能只因描述子相近就當成真陀螺；無模型性能聲稱。
3. 接影子狀態機與聯合指派，涵蓋斷軌及未換ID的交換候選；完成回歸與獨立凍結評估，
   再另行決定正式綁定。沿用原分支，不另開分支／工作樹或push。
