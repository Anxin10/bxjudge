# BXJUDGE 軌跡與身分通用規則

日期：2026-10-26。狀態：規則已制定；下方逐項區分目前實作與後續要求。
適用範圍：陀螺影片的偵測、碎片接續、X／B 身分與裁判證據。以可重現證據決定，
不按影片名稱、特定 track ID、陀螺固定顏色或某一段成功案例寫例外。
本文件補充動態裁判設計；不改既有比賽規則、人工修訂、校準否決與評估 ledger。

## 一、保留規則

**G01 原始證據保留。** 原片、來源 SHA-256、原始影格編號、時間／FPS、座標大小、
偵測類別／框／信心分數、原始 track ID 與模型／設定版本均須可追溯。
接續只建立新成員關係，不抹掉原始觀測；同格擇一後，被取代的框與分數另存。
原人工提交及已覆核判決保留，修訂另存；新試跑與舊人工結果分開，不默默覆寫。

**G02 未接續不等於不同物件。** 因觀測不足、模型限制或候選不唯一而拒絕，只表示
保留兩段與未知狀態。不得把拒絕案例自動標成「不同顆」、負樣本或裁判失敗真值。
本次五組案例保留作開發與回歸證據，不因日後接回就刪掉原拒絕紀錄。

## 二、通用判斷規則

**G03 三層判斷分開。** 分別記錄「軌跡能否接續」、「是 X 還是 B」、「能否裁判」。
接回軌跡不代表已辨識 X／B；辨識 X／B 不代表物理分離、落地或勝負已確定。
軌跡 ID、顯示顏色與框中心均不能充當機械接合或真實身分的替代證據。

**G04 身分依每場建立。** X／B 來自該場可靠的發射前證據，或明確標記為人工初始化
的該場確認；不得按中途畫面左右重新命名，不把某場「深 X／淺 B」套到其他場。
同一設定出現兩種矛盾身分時保留未知，不能用多數決選一方。跨回合、換手或新比賽
必須有明確邊界與新身分依據，不能靜默沿用上一場模板。

**G05 座標、時間與缺口有明確語意。** 同一幾何判斷的框與區域使用相同座標系；保留
原始影像座標與對位證據，不補失敗對位。速度除以實際來源影格差，期限以影片時間算。
「沒有偵測」與「已有偵測但對位未知」分開，後者不能偽裝成普通漏偵後重新定錨。
缺格可用於帶有未知區間的運動估計，但不得產生不存在的框或聲稱已觀測到完整過程。

**G06 短缺口接續須同時滿足證據。** 時間向前且在配置範圍內、位置／尺度／運動相容、
前後候選互相唯一、身分錨點無矛盾，才可建立接續。速度使用短時間內多格實際觀測，
不讓單一框抖動直接代表真實反向。新掛載／新釋放不能被接成另一顆的延續。
若有多個可行候選，即使某個分數最高也不強行合併。

**G07 重疊交接以實際共格觀測為準。** 所有共同影格均須有兩方實際觀測並通過重疊
檢查；已有真實位置時不從尾端反向外推。只在單格碰撞時框重疊，不能據此認定同一顆；
運動、尺度、候選唯一性與身分條件仍須成立，接續維持人工覆核。

**G08 長遮擋與碰撞另行驗證。** 超出短接續範圍，不能單靠放寬時間、附近位置、相同
顏色或之後的勝負強接。後續方法需同場可靠身分參考、多格外觀與時空證據、可見性
及多候選檢查。模糊或相似物件無法區分時保留未知；外觀相似不能推翻相反身分錨點。
這是後續實作要求，現版沒有通過驗證的長缺口重新辨識能力。
詳細規格見[遮擋與部分碰撞後重新辨識](2026-10-26-occlusion-collision-reidentification.md)，目前僅設計、尚未實作。

**G09 未知不得變成有利的裁判證據。** 有效但身分未知的陀螺可能是另一方，必須覆核；
不能因無法對位、漏偵或未接回，就當作已出界、停轉、離場或認定另一方獲勝。
自動接續仍保留 `identity_join_requires_review`，不因片段數減少而取消覆核。

## 三、人工確認與驗收規則

**G10 只補必要片段，人工可以不知道。** 後續斷點核對使用「同一顆／不同顆／看不清」；
X／B 是另一欄，不能被迫二選一。保存來源片 SHA、來源影格區間、候選成員、確認人／
來源與修訂版本。已有覆核不要求整批重做；需要新證據時只核對新增或受影響區間。
三態斷點互動介面已實作局部短片核對與不可覆寫保存；五組已人工完成，四組同一顆、
一組無法判定，另有第5組藍框為發射頭端的端點註記。仍不代表全場scope已驗證。

**G11 評估保留覆蓋率與錯誤代價。** 分開報告指派正確、不一致、未知、錯接／錯側、
未接回及人工覆核率。未知不算判對，也不能從分母消失。軌跡總數只是診斷，可能含
誤偵或賽後拾取，不是物件數、斷點次數或準確率。不能只以少幾條軌跡選模型。
開發用的已看過影片與獨立驗收分開；人工初始化或用來調參的資料不能再冒充盲測。
最終準確率、人工覆核率與完整 wall-clock 時間一起驗收，VLM 是否包含必須明寫。

**G12 規則統一、參數可驗證。** 通用規則不等於所有解析度／FPS／模型共用同一組數字。
參數集中 YAML 並記錄版本；先在指定座標尺度與採樣條件驗證，再擴大到不同場景。
不得為特定影片或 ID 寫例外，也不加入舊資料相容 fallback。修改估計器即使沒有改門檻，
也可能改變接受集合，仍須回歸與獨立驗證。沿用目前分支，依實作→測試→唯讀審查→
親自核實→修正與驗證→提交的流程推進。

## 五、現版參數僅作實作對照

唯一執行設定為 `config/launch_phase.yaml`，本次不更動。下表是制定規則時的快照，
不是另一份供程式讀取的設定，變更時須同步核對文件。

| 設定 | 現值與單位 |
| --- | --- |
| `held_s` | 0.2 秒；身分錨點要求 `max(2, ceil(held_s × FPS))` 連續實際來源影格 |
| `body_margin_px` | 12 px；發射器區域近身證據，不能當作機械接合 |
| `link_gap_s` | 0.12 秒；短缺口／短重疊的現行範圍 |
| `link_error_px` | 24 px；當前推論影像座標的相容位置誤差 |
| `link_scale_ratio` | 1.5；框對角線尺度比上限 |
| `link_min_direction_cos` | 0.5；達到速度檢查條件時的方向相容門檻 |
| `link_velocity_error_px_s` | 120 px／秒；估計速度差上限 |
| `link_min_speed_px_s` | 15 px／秒；現行動靜與方向檢查的速度門檻 |
| `link_overlap_iou` | 0.6；每個共同影格的實際框重疊下限 |
| `link_velocity_frames` | 5 個來源影格的時間範圍；對實際觀測位移／實際影格差取中位數 |
