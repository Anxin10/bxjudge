## 判定與資料流

1. 在原始來源格上辨識三態。**已證實掛載**以同一原生陀螺、唯一鄰近發射器及完整的連續掛載觀測為操作定義。**可靠分離**需要該掛載段緊接同一發射器仍在畫面、兩框連續拉開的觀測，分離起點與確認格分開記錄。兩框只在某一格靠近、發射器消失、軌跡斷格、互相衝突與框外截切時，證據不足的區間為**無法確定**。完整的新掛載段可以建立下一次嘗試的證據，無法確定的格維持原狀。
2. 先用現有 held_s、separation_s 與 body_margin_px，沿用 Task 2 的樣本數換算。先驗證已有的直接分離資料能否涵蓋兩個案例。210934 B 的發射器 4、214640 X／B 的發射器 5／14 有可核對的連續段；210934 X 的發射器編號在 6／12 之間變動，先檢查證據是否足夠，再決定是否需要另做發射器連續性。以框距作為可觀測證據，首次物理接觸仍需獨立佐證。
3. 用回合內有效的原生軌跡歸屬把分離證據交給 X／B，確認區間不得跨回合。重掛載或第二次發射與前一次活動重疊、同一側有多個不同的候選、分離前已存在雙方有效交手觀測時，留待覆核。保存原生軌跡、發射器、掛載起訖、分離起點與確認格，原始觀測仍可回查。
4. 兩顆各有可靠分離時，各自從分離格起算同一份 375 ms 期限，只用分離後的真實觀測搜尋 settle。單側仍無法確定時，該側沒有落地期限，落地狀態為未知，需覆核。規則層應能區分未知與已證實未落地，避免加計發射失誤或重複失誤罰分。保存各側截止格供逐格核對，並確認人工覆核仍可填入確定結果。
5. 先交付分段及期限；後續再用兩側可信分離及準備段的證據，界定 R55 對位／未分配框的檢查起點。只有證據支持的準備段才可排除。入袋框角抖動與物理落地回歸（D265、G555、202324 第 2 回合 f1735）照核准順序接在後面。

## 驗證順序

- **RED。** 建立長掛載、開頭看不到發射器、兩方不同時分離、已掛載後遮擋、發射器 ID 不明及回合中途拿起再放回的案例。證明原本的首筆框起算會提前截止，並驗證未知分離不能造成罰分。
- **GREEN。** 在現有發射分段、落地分析與裁判入口接入最小改動。驗證連續格、原生軌跡歸屬、未知區間、不同幀率下的原始時間門檻、覆核輸入與重新載入後的結果。
- **實片證據重放。** 使用已保存的框與對位先在 CPU 上重算兩支影片，逐側列出原本截止格、新證據與可確認／未知。若實片證據不足，記錄是哪個格、哪個物件缺證據。人工勝負真值與自動分離候選分開保存。
- **回歸。** 全套 CPU 測試，必要時再用原始權重、校準與影片端到端重判。啟動任何 GPU 工作前先用 nvidia-smi 核對，並核查 WSL 內的模型工作。逐回合列出欄位及得分變化，檢查是否引入錯判、假發射或假罰分。
- **交付。** 沿用現有分支，在隔離的 git archive 驗證，只提交本次檔案。Rust、HUD、場地關鍵點的既有工作與原始資料留在各自範圍，交 Claude 審查。
