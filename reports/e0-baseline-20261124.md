## 1. 結論

1. **追蹤配對本身幾乎沒有錯：**
   - 每 0.25 秒一個關鍵幀，軌跡層級的 IDF1 為 0.95–1.00；
   - HOTA(track) 為 0.92–1.00；
   - ID Switch 在 production 是 0 次，v7 是 2 次。

   因此在這 3 支影片上，**E2（雙向縫合）和 E3（圓弧預測）幾乎沒有改善空間**，優先順序應該往後調。

2. **真正的瓶頸是 X／B 身份沒有被指派：**

   | 模型 | 有被指派身份的比例 | 指派正確率 | 指派錯誤 |
   |---|---|---|---|
   | production | 28%（只有 201410 一支） | 100% | 0 |
   | v7 | 14%（只有 201444 的 X） | 100% | 0 |

   - 「不強行指派」的原則有確實做到；
   - 但身份錨定的覆蓋率太低，主要原因是：
     - `identity_unanchored`；
     - `launch_timing_unknown`；
     - `launch_release_unobserved`（發射瞬間沒觀察到放開）。

3. **3 局都沒有產出判決：**
   - Finish Macro-F1 = 0；
   - 勝方正確 0/3（3 局真值皆已由使用者人工複核確認）；
   - 人工覆核率 100%；
   - 停轉時間誤差無法計算（沒有任何預測）。
   - 共同的阻擋原因是 `calibration_geometry_missing`；另外 201410 有 `stop_evidence_missing` 和 `X_stop_reversed`／`B_stop_reversed`。

4. **v7 在端到端測試沒有比 production 好：** 身份覆蓋率是 14%，production 是 28%。發射器容錯修改（phase5）也沒有改變任何身份或追蹤指標。

5. **建議調整後續順序：**
   E1 校準缺口 ＋ **新增 E1b 發射身份錨定覆蓋率** → E7（launcher／邊緣 ROI）→ E4（停轉）→ E2 → E3 → E5 → E6。
   - E1b 的方向：在發射器偵測和放開瞬間的觀察都可靠時，提高身份錨定的成功率；仍然不允許強行指派。

處理時間取自單獨佔用 GPU 的重跑（`timing-*`）。第一次基準時 GPU 同時在跑關鍵幀偵測，時間偏長，不採用。重跑後所有身份與追蹤指標都和第一次完全相同，代表結果可以重現。

**指標定義**（`scripts/e0/e0_eval.py`）：
- **side-IDF1**：把輸出的 `side` 直接當成 ID，固定對應 X→X、B→B。沒有指派（abstain）算 IDFN，不算 IDFP。
- **track-IDF1**：用 `track_id` 和真值 X／B 做最佳的一對一對應。
- **HOTA**：用中心距離相似度 S = 1 − d／(框對角線的一半)，在 α = 0.05…0.95 下計算。
- **ID Switch**：同一個真值物體在相鄰關鍵幀之間，預測 ID 改變的次數。

## 5. 限制

1. **逐框身份是依外觀推得的。** 使用者已人工確認 3 局的 X／B 顏色與勝負（2026-11-24）；212 個關鍵幀上的每個框則是依這組顏色對應判定，沒有逐框人工核對。標成 U 的物體不計分，也不算誤報。
   - 真值曾修訂一次：初版（sha256 `f4cd6f17…`）把 201331 判為 B 勝、201444 列為不確定；人工複核後改為 201331 X 勝、201444 B 勝（`2853566a…`）。身份與追蹤指標兩版完全相同，只影響回合指標。
2. **候選框來自 production 偵測器。** 所以 DetA 和 HOTA(track) 對 production 有利；偵測漏框只記錄了 3 幀。
3. **0.25 秒取樣看不到更短的交換。** 只維持不到 0.25 秒的 ID 交換看不到，track switch 可能被低估。若要測碰撞瞬間，需要再加碰撞前後的逐幀標註（原計畫 E0-a 的第二部分，這次沒做）。
4. **樣本很小。** 只有 3 支影片、3 局、212 個關鍵幀，數字只能看方向，沒有統計顯著性。
